# 报告输出

写报告、说明文档、README 之前读这份；报告交稿前的审校润色看第七节。它管的是结构与口径，字句层面的规则仍按主规程第 0、3 节执行。

报告与一般说明文档的差别在两处：一是数字要经得起追问，二是结论与建议必须分开落地。这两处失手，读的人不会说你文笔不好，会说你没弄清楚。

## 一、结构

**开篇**先交代这份文件是什么、给谁看、输入输出是什么。三句话足够：这些数据从哪来、覆盖谁、要回答什么问题。让读者在第二屏就知道该不该继续读。

**主体**按研究问题或分析步骤组织，不按数据表的列序组织。一个问题一节，节内先写看到什么、再写这意味着什么。方法说明另起一节，不要混在结果里带过去。

**结尾**分三层：结论、行动项、下一步。结论是数据支持得住的那几句判断；行动项是谁在什么时候做什么；下一步是这次没做完、需要什么条件才能接着做的部分。

## 二、数字呈现

每个数字都要能就地读出分母与出处。写在这句里，或者紧前一句里。

- 「累计口径」要指明是谁的累计：不是「累计流失 4,200 个」，而是「从 7 月 1 日到 7 月 31 日注册的账号里，累计流失 4,200 个」。
- 「当期」要换成具体时点：不是「当期留存 31.4%」，而是「7 月注册的账号，七天后留存 31.4%」。
- 比例后面跟 ME，区间半宽一律写作 ME，按 1.96×√(p(1−p)/n) 算，单位百分点。同时写明它只覆盖随机抽样误差，不含配额样本的选择偏差。
- 分子分母同现。「流失了 12%」不好，「10,560 个里流失 1,267 个，占 12.0%」好。
- 组间比较要写清比较的是哪两组，不要说「显著高于其他组」。

## 三、表格使用

参考性内容做表格：码表、参数对照、样本构成、判断项、版本对应。论证与推理写段落，不要拆成条目。

表格排序要有依据，用升序或者按语义分组，不要随手排。每条交代来源，分清哪些是行业标准、哪些是项目约定——把项目约定写成行业标准，是需求方一眼能看穿的错误。

表格里同一件事的写法要与正文一致。同一份报告里，一处写「留存率」一处写「次日留存」，读的人会以为你在说两个指标。

## 四、结论与建议

结论只写数据支持得住的部分，并明确区分：

- 关联与因果。相关不等于因果，能在数据里看到的是关联，要判因果得说明还需要什么条件。「A 组流失率高于 B 组」是关联；「X 导致流失」需要证据。
- 组内与组间。组间差异常常被组内差异盖过，两个都写出来，读者才知道差异有多大。
- 样本内与样本外。配额样本能说明组间对比，不能外推成总体分布，要写清能读到哪一步。

建议要落到具体行动：谁做、做什么、什么时候做完、看什么指标判断成败。停在「需要进一步研究」「建议持续关注」不算建议，那是把问题还给读者。

建议与结论分开放。结论是「看到了什么」，建议是「所以做什么」，两者混写会让读者分不清哪一句是事实、哪一句是你的主张。

## 五、方法说明

模型族、连接函数、样本量、参照组、诊断结果，按这个顺序写成一段，不要打散混进结果里。这一段的读者是来复核的，写得整齐比写得漂亮要紧。

方法交代不全的后果不是被批评，是被误读：没写参照组，读者会拿系数当成绝对效应；没写诊断结果，读者不知道模型假设有没有被检验过。

## 六、风险与限制

下面四类内容必须把限定条件、反例和风险摆出来：

- 事实没核实过的。
- 结论带前提的。
- 涉及安全与合规的。
- 可能让用户吃亏的。

写法是把限定写在心里那句话的前面，不要塞在末尾补一句。先说这批数据的分母是什么、覆盖谁、哪些人不在里面，再说结论。风险提示、安全警告、合规声明里，「需要注意的是」这类提示语可以用，不受禁用词表约束。

## 七、审校与润色

已成稿的定量分析报告交出去之前，按这一节过一遍。读者假定是业务方，比如游戏运营人员，而不是分析者本人。要改的是表达：口语换书面，模糊词换规范词，比较的主体与依据补全，统计表述统一。改完之后仍是同一份报告，数字、结论方向与表格结构都不许动。

### 7.1 改稿不得越过的三条线

改之前先把这三条钉死，任何改写都不得与它们冲突。

- 读数逐字保留：章节号、表号、表头、指标名、样本量、分数、百分比、±pp、OR、95%CI、p 值，以及表注里的统计口径，一处不动；专有名词与编号照原文，如 RO、MMORPG、Q2、Q3、Q4、MOBA、PC、OR、pp、主样本、补充样本；原有结论方向同样保留，显著与不显著、更高与更低、校正后成立的项数都不改。
- 不得新增或改动实质：不添原文没有的数据、结论、因果判断；不把未校正显著写成显著；不把「未观察到差异」写成「两组相同」；不删减显著项；不合并或拆分表格；不改数。
- 表格与表注：表格原样保留；表注可改成规范说明，含义不得变，「表里」改「表中」，「这一行」改「该行」，「少 1 人」改「少 1 人，系该题存在缺失值所致」。

### 7.2 口语转书面

| 原表述 | 规范表述 |
|---|---|
| 这一节 | 本节 |
| 这一层 | 本层 |
| 这个数 | 该数值 |
| 这一批人 | 该批人群 |
| 这一处／这一块 | 该方面／该模块 |
| 多出 | 新增 |
| 挑出 | 筛选出 |
| 说不清 | 尚无法明确 |
| 把握不足 | 统计把握不足 |
| 没有观察到 | 未观察到显著差异 |
| 不是判定相同 | 并不表示两组人群相同 |
| 两句话可以同时成立 | 可以同时得到以下两点结论 |

### 7.3 补全主语、宾语与依据

| 原表述 | 规范表述 |
|---|---|
| 分组只看 Q2 | 分组依据仅为 Q2 |
| 算前者 | 归为前者 |
| 算对照 | 归为对照组 |
| 进同一个模型 | 进入同一模型 |
| 这一层基数是 | 本层模型基数为 |
| 把比较多项带来的偶然显著排除掉 | 经多重比较校正以排除偶然显著 |
| 同一次校正 | 同一轮多重比较校正 |
| 这个数是控制年龄与性别之后的相对倍数，不是概率差 | 该数值为控制年龄与性别后的相对倍数，并非概率差 |
| 不带模型 | 不包含模型调整 |

### 7.4 统计表述规范

比值比首次出现写「比值比（OR）」，此后一律写 OR。置信区间写「95%置信区间」。校正后 p 写作「校正后 p」。平均勾选个数写「平均勾选数量」；「多勾一到两个」写「平均多勾选 1 至 2 个」。未调整的百分点差写「未调整百分点差」。

### 7.5 长定语与段落逻辑

长定语保留，不缩成简称。「听说过至少一个《RO》IP 游戏的人」「其余 MMORPG 玩家」「玩过《RO》IP 游戏的人」「没玩过的人」按原样写，不简写成「RO 听说者」这类自造词。

每一段的推进顺序固定：先说比较对象、样本与模型，再说比较了多少项、校正结果如何，然后列显著项，最后解释方向与边界。破碎短句合并，减少「这」「那」「它」这类模糊指代。「把……放在同一道题上」改「置于同一指标体系中」，「这一处要留一层余地」改「需保留一定解释余地」，「更可能来自」改「更可能源于」。数字与单位之间按规范处理，引号统一。

### 7.6 交付形态

一次审校交三样：修订后的全文，保留章节与 Markdown 表格；修改说明清单，按段落列出主要修改类型和典型例子；待人工确认项，列出涉及统计口径、组名统一、表格原样保留等不能擅自决定的事项。
